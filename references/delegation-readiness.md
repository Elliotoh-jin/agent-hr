# Delegation-readiness interview

Run this with the delegator (the human whose judgments queue) before drafting a
contract, whenever their criteria are tacit. Ask in order; each answer feeds a
specific contract field. Socratic style: one question at a time, follow tensions.

## 1. Secondary gains — why hasn't delegation happened already?

"Doing every judgment yourself for months: what are you getting from that?"
Leaders who don't delegate are usually *gaining* something, not merely failing to act.

- **Judgment muscle / learning** → real gain. Split the queue: judgments that build
  the delegator's skill stay human (possibly forever); judgments that build nothing
  are the delegation frontier. Ask: "name a recent judgment that built no muscle" —
  those name the first contract's scope.
- **System visibility** ("delegating makes it a black box") → not a blocker: contract
  requires delegated outcomes to surface in the shared brief + sample audits.
- **Control / anxiety after incidents** → address with the safety line (one-strike
  stop), not by withholding delegation.
- **Nothing — just never defined the handover** → go straight to the gate.

## 2. The conversion trigger — when is "later" ?

"When will delegation be ready — what exactly, accumulated to what point, flips
the switch?" If the answer is "later, once enough is recorded," pin it down:
an undefined "later" never arrives.
Then apply the convexity argument: failed delegation is cheaply discarded, successful
contracts replicate infinitely — so the correct move is a small experiment now, not
more accumulation. (Exception: canonical-state writes have a cleanup tail — cover
with the safety line, don't postpone.)

## 3. Specification triage — why can't the outcome be written down?

"When you try to write the acceptable outcome, where exactly does it stall?"
Three distinct difficulties, three distinct spec forms:

| Difficulty | Signature | Spec form it demands |
|---|---|---|
| Tacit criteria | "I know it when I see it" | **Exemplars**: one "like this" artifact + one "never like this" |
| Goodhart distrust | "If I give a number they'll game the number" | **Falsifiers**: "it failed if…" list — distortion-resistant, and it becomes the verifier's entire rubric |
| Criteria form during the work | "I don't know what good is until I'm in it" | **Midpoint gate**: direction check at ~20%; capture the criteria that emerged and fold them into the contract (version bump) |

If the answer is "specifying costs more than doing it myself" — classic delegation
trap; solved by contract reuse, not by skipping the spec.

## 4. Grading structure — who verifies?

"Your last delegation failure: was the spec missing, or did the performer grade
their own homework?" A spec without a separated verifier still fails — the verifier
must receive only the contract and the diff, never the performer's reasoning.
Agent self-grading fails from response bias, not dishonesty, so it cannot be
trained away — only structured away.
